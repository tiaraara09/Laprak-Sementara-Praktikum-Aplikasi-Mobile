📘 Laporan Praktikum 5: Arsitektur Navigasi

Named Routes & Bottom Navigation Bar

Tiara Azizah | Informatika 24 - Universitas Andalas

📖 BAB I: Pendahuluan

1.1 Tujuan Praktikum

Praktikum ini memiliki beberapa tujuan utama dalam pengembangan arsitektur aplikasi mobile, yaitu:

  • Menerapkan Named Routes untuk navigasi terpusat dan rapi[cite: 20].
  • Membangun menu bawah (Bottom NavigationBar) ala aplikasi modern[cite: 20].
  • Mengintegrasikan Dashboard, Riwayat, dan Profil dalam satu wadah[cite: 20].

1.2 Alat dan Lingkungan Kerja

Flutter SDK[cite: 20] VS Code / Android Studio[cite: 20] Android Emulator / Device[cite: 20]

📖 BAB II: Dasar Teori

Dalam pengelolaan struktur navigasi lanjutan pada Flutter, terdapat beberapa komponen utama yang dipelajari:

  • Named Routes: Mendefinisikan nama string untuk setiap halaman di dalam MaterialApp. Hal ini mencegah *spaghetti code* saat aplikasi memiliki banyak layar[cite: 20]. routes berfungsi sebagai tabel peta rute aplikasi, sedangkan initialRoute menentukan halaman pertama yang dimuat ('/')[cite: 20].
  • Bottom Navigation Bar: Menu navigasi di bagian bawah layar yang mengontrol tampilan utama (body) tanpa berpindah Scaffold secara penuh[cite: 20]. Parameter currentIndex melacak indeks tab aktif, sementara items memuat daftar ikon serta label tab[cite: 20, 21].

🛠️ BAB III: Langkah Kerja & Implementasi

Pada praktikum ini, struktur aplikasi dikembangkan menggunakan pendekatan terpusat untuk rute serta manajemen state tab navigasi bawah.

📌 3.1 Mendaftarkan Named Routes di main.dart

Parameter home pada MaterialApp dihapus dan digantikan dengan initialRoute serta routes untuk memetakan rute navigasi aplikasi[cite: 21, 23].

MaterialApp(
  debugShowCheckedModeBanner: false,
  title: 'Expense Tracker Final',
  theme: ThemeData(primarySwatch: Colors.amber),
  initialRoute: '/',
  routes: {
    '/': (context) => const MainScreen(),
    '/add': (context) => const AddTransactionScreen(),
  },
)

📌 3.2 Membuat Penampung Tab (main_screen.dart)

File ini menggunakan StatefulWidget guna menangani perubahan status indeks tab aktif (_selectedIndex) dan menampung daftar halaman utama seperti Dashboard, Riwayat, serta Profil[cite: 21, 24].

class MainScreenState extends State<MainScreen> {
  int _selectedIndex = 0;
  
  final List<Widget> _pages = [
    const DashboardScreen(),
    const Center(child: Text("Halaman Riwayat")),
    const Center(child: Text("Halaman Profil")),
  ];

  void _onItemTapped(int index) {
    setState(() {
      _selectedIndex = index;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: _pages[_selectedIndex],
      bottomNavigationBar: BottomNavigationBar(
        currentIndex: _selectedIndex,
        onTap: _onItemTapped,
        selectedItemColor: Colors.amber[800],
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Beranda'),
          BottomNavigationBarItem(icon: Icon(Icons.history), label: 'Riwayat'),
          BottomNavigationBarItem(icon: Icon(Icons.person), label: 'Profil'),
        ],
      ),
    );
  }
}

📌 3.3 Pemanggilan Rute via FloatingActionButton

Pada file dashboard_screen.dart, fungsi navigasi tombol tambah transaksi diubah agar memanggil rute terpusat yang telah didaftarkan[cite: 24, 25]:

floatingActionButton: FloatingActionButton(
  backgroundColor: Colors.amber,
  child: const Icon(Icons.add),
  onPressed: () {
    Navigator.pushNamed(context, '/add');
  },
)

✅ BAB IV: Kesimpulan

Melalui praktikum ini, penerapan Named Routes berhasil diintegrasikan untuk membuat manajemen rute dan navigasi aplikasi menjadi lebih terstruktur, terpusat, serta menghindari kerumitan pemanggilan halaman secara langsung[cite: 20]. Kombinasi dengan Bottom Navigation Bar memungkinkan perpindahan antar menu utama (Beranda, Riwayat, dan Profil) berjalan secara mulus dalam satu kerangka antarmuka yang efisien.
